## 1. Introduction

H-GNN is a physics-informed learning framework for orbital dynamics where part of the Hamiltonian is known (classical two-body gravity) and part is unknown (complex interactions, perturbations, unmodeled effects).

The project objective is to learn the unknown correction term while preserving Hamiltonian structure so long-horizon rollout remains stable and physically consistent.

Core idea:

`H_true = H_known + H_unknown`

Instead of directly learning state updates, H-GNN learns a Hamiltonian correction and evolves the system through Hamilton's equations using a symplectic integrator.

---

## 2. Problem Statement

### Real problem

For real satellites, two-body dynamics alone is incomplete. Trajectories from TLE/SGP4 include effects that a simple analytic baseline does not fully capture.

### Why normal neural networks fail here

1. Standard NN predictors do not preserve symplectic structure.
2. Non-symplectic rollout accumulates drift over time.
3. Gradient signals can collapse when correction scale is small relative to base physics gradients.
4. Good short-horizon fit can still fail at medium/long horizons.

---

## 3. Solution Ideology and Scientific Position

The project follows a structure-first philosophy:

1. Preserve physical laws in the model class (Hamiltonian formulation).
2. Preserve geometry in the integrator (symplectic update).
3. Learn only what physics does not already explain (correction term).
4. Scale correction magnitude in a numerically stable way (`dt^2`, learnable `alpha`, and normalization).

This is why H-GNN is not a black-box forecaster; it is a constrained neural-physics model.

---

## 4. Mathematical Formulation

Primary model form used across this repo:

`H_theta = H_base + dt^2 * alpha * (1/N) * sum_{i,j} Phi(z_i, z_j)`

Where:

1. `H_base`: two-body Keplerian Hamiltonian.
2. `Phi`: learned pairwise interaction potential.
3. `dt^2`: backward-error-aligned scaling for Störmer-Verlet.
4. `alpha`: learnable correction magnitude.
5. `1/N`: normalization to stabilize force scale with system size.

Dynamics are generated by Hamilton's equations:

1. `dq/dt = dH/dp`
2. `dp/dt = -dH/dq`

Integrator: Störmer-Verlet / symplectic schemes in `h_gnn/integrators/symplectic.py`.

## 6. Data Pipeline

### Source

TLE catalog from `satellites.tle` (CelesTrak-derived in your workflow).

### Flow

1. Parse TLEs and propagate trajectories.
2. Filter LEO satellites as needed.
3. Convert trajectories into supervised pairs with horizon offset:
   1. `(q0, p0)` at time `t`
   2. `(q_target, p_target)` at time `t + horizon`
4. Use stride overlap to increase sample count.

Main conversion API:

`convert_to_hgnn_format(...)` in `h_gnn/data/tle_loader.py`.

## 8. Training Methodology

### Stable training recipe used in improved TLE training

From `train_on_tle_improved.py` and validated runs:

1. Physical-scale normalization constants:
   1. `Q_SCALE = 10000.0` km
   2. `P_SCALE = 10.0` km/s
2. Energy conservation auxiliary loss with small weight.
3. AdamW optimizer + scheduler.
4. Gradient clipping.
5. Learnable `alpha` initialized and tracked.
6. Symplectic rollout training objective over horizon windows.

### Important stability points discovered

1. `alpha` must be initialized and monitored.
2. Loss magnitudes must be normalized by physical scales.
3. Naive settings can lead to correction collapse or non-learning.
4. Horizon-specific behavior matters (short/medium/long differ strongly).
